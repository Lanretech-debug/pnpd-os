# PNPD Runtime Readiness Usage

## Overview

Runtime readiness reports are **advisory-only local evidence snapshots** generated by the PNPD orchestrator dry-run. They capture the runtime state of a repository at a point in time, including branch, clean/dirty status, CI classification, safety posture, and governance authority.

These reports support **Owner and Codex review**. They provide structured, tamper-evident evidence for decision-making.

**They do not authorize action.** No report can approve a merge, trigger a dispatch, enable deployment, or bypass Owner or Codex gate authority.

## Commands

### Stdout-only report (`--runtime-readiness`)

```bash
node scripts/pnpd-orchestrator-dry-run.mjs --runtime-readiness
```

- Prints JSON to stdout.
- Writes **no files**; no files written.
- Does **not** create `.pnpd/runtime-readiness/`.

### Local write report (`--write-runtime-readiness`)

```bash
node scripts/pnpd-orchestrator-dry-run.mjs --write-runtime-readiness
```

- Prints JSON to stdout.
- Writes exactly **one JSON file** under `.pnpd/runtime-readiness/`.
- The written file is **byte-identical** to stdout.
- Generated files are **gitignored** (`.gitignore` includes `.pnpd/runtime-readiness/`).
- This is a **create-only local write**. It does not update, delete, or modify any existing files.

### Schema and fixture validation (`--phase 1h`)

```bash
node scripts/pnpd-validate-schemas.mjs --phase 1h
```

- Validates the runtime readiness schema (`.pnpd/runtime-readiness.schema.json`) and all 13 fixture files under `tests/fixtures/pnpd/runtime-readiness/`.
- This is an **explicit-only** validator invocation. It is not part of `npm run validate` (which runs phases 0, 1b, 1c, and 1f).
- It is run explicitly in CI as an independent step.

## Report contents

Each runtime readiness report is a JSON object with the following top-level fields:

| Field | Description |
|-------|-------------|
| `schemaVersion` | Schema version string (`"1.0.0"`) |
| `recordType` | Record type identifier (`"pnpd.runtimeReadiness"`) |
| `repo` | Repository metadata (path, branch, etc.) |
| `source` | Runtime source context, including remote CI observation status |
| `validation` | Schema and fixture validation results from the current run |
| `dryRun` | Dry-run classification (e.g., `"CODEX_REVIEW_REQUIRED"`) |
| `authority` | Governance authority model (Owner, Codex, AgentBridge roles) |
| `safety` | Safety posture flags (advisory-only, no dispatch, no deployment, etc.) |
| `readiness` | Overall readiness status (e.g., `"reviewBlocked"`) |
| `integrity` | Content hash for tamper-evident cross-reference |
| `audit` | Timestamp and record identifier fields |

### Conservative expected values

When run locally without remote CI observation:

- `source.remoteCiObserved`: `false`
- `dryRun.classification`: `"CODEX_REVIEW_REQUIRED"`
- `readiness.status`: `"reviewBlocked"`

These are the expected values for a local, non-CI invocation. Remote CI runs populate additional fields.

## Generated files

- **Directory:** `.pnpd/runtime-readiness/`
- **Filename format:** `YYYY-MM-DDTHH-mm-ss-SSSZ-{contentHashPrefix8}.json`
- **Example:** `2026-06-14T14-52-40-123Z-a1b2c3d4.json`
- **Git status:** Gitignored — must not be committed.
- **Created only by** `--write-runtime-readiness`. The stdout-only flag (`--runtime-readiness`) creates no files.

## CI validation

The PNPD CI workflow (`.github/workflows/pnpd-ci.yml`) validates runtime readiness behavior on every push and pull request to `main`:

1. **Phase 1H validator** — runs `node scripts/pnpd-validate-schemas.mjs --phase 1h`
2. **Stdout report validation** — asserts schema, safety, authority, and integrity fields; verifies no `.pnpd/runtime-readiness/` directory is created
3. **Write-mode validation** — asserts exactly one file written, filename format with hash prefix, byte-identical to stdout, full field assertion
4. **Incompatible flag smoke** — verifies `--write-runtime-readiness --json` and `--write-runtime-readiness --no-write` are rejected
5. **Generated state cleanup** — removes all PNPD state directories and temp files (runs even if prior steps fail)
6. **State directory check** — verifies no PNPD state directories remain
7. **Clean working tree check** — `git diff --exit-code`

## What these commands do not do

Runtime readiness commands **do not**:

- Authorize or trigger dispatch
- Authorize or trigger deployment
- Mutate GitHub repositories or call GitHub APIs; no GitHub/API mutation
- Authorize merges or pushes
- Certify production readiness
- Handle or expose secrets
- Grant AgentBridge approval authority
- Bypass Owner or Codex gate authority

## Governance warnings

- **Owner remains final authority.** No report overrides owner decision-making.
- **Codex audit is required before merge.** Reports provide evidence for Codex review; they do not replace it.
- **AgentBridge coordinates only.** It does not approve, merge, deploy, certify, dispatch, or bypass gates.
- **Runtime readiness reports are advisory-only.** They describe state; they do not authorize action.
